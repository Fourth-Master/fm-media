# FM影媒 · 架构说明

## 1. 分层

```
Features (SwiftUI 视图)
      │  读取/写入
      ▼
Core (服务层，@MainActor 状态对象)
      │  调用
      ▼
Provider (RemoteFileProvider 协议实现)
      │  HTTP / 文件系统
      ▼
本机沙盒 · 媒体服务器 · 云盘 · WebDAV · SMB
```

- **Features**：只负责展示与用户交互，状态来自注入的 `ObservableObject`。
- **Core**：业务状态与持久化，全部在主线程（`@MainActor`）；耗时 IO 一律 `await` 到后台。
- **Provider**：把"目录浏览、取流、上传下载"抽象成统一协议，视图层不区分本机还是远程。

## 2. 全局状态对象

| 对象 | 职责 | 注入位置 |
| --- | --- | --- |
| `AppSettings` | 播放/字幕/库/传输偏好，JSON 持久化 | `FMApp` |
| `AppDatabase` | 用户添加的来源列表，密码存钥匙串 | `FMApp` |
| `LibraryStore` | 媒体库条目、筛选排序、收藏、播放进度 | `FMApp` |
| `TransferManager` | 传输队列与调度 | `FMApp` |
| `PlayerPresenter` | 全局播放请求（全屏播放器入口） | `FMApp` |
| `SubtitleLibrary` | 影片 ↔ 下载字幕的关联 | 单例 + 环境 |

## 3. 数据模型要点

- `MediaCode`：番号解析结果（编号 / 破解 / 字幕 / 额外 token）。
- `MediaSourceConfig`：一个来源的完整描述；`secret` 走 Keychain，其余字段 Codable。
- `FileEntry`：本机与远程统一的文件条目（路径语义由 Provider 决定）。
- `MediaItem`：媒体库条目，包含本地路径或 `remoteStream`、封面引用 `ImageRef`（可带鉴权头）、字幕列表、NFO 字段。
- `TransferTask`：一次传输的完整状态（方向、进度、速率、错误）。

## 4. 关键流程

### 4.1 扫描媒体库

```
LibraryStore.scan(sources:)
  └─ Task.detached → LibraryScanner.scanLocal(source:)
       ├─ 遍历一级目录（番号文件夹）
       │    ├─ MediaCodeParser 解析文件夹名
       │    ├─ 选主视频（同番号 → 体积最大）
       │    ├─ 匹配字幕 / poster / fanart / nfo
       │    ├─ 读取 extrafanart/ 预览图
       │    └─ NFOParser 解析元数据
       └─ 根目录散落文件按番号聚合
  └─ 合并保留远程条目 → 恢复播放进度 → 持久化
```

### 4.2 播放

```
View → PlayerPresenter.play(request)
  → fullScreenCover(PlayerScreen)
      → PlayerViewModel.start(preferred:)
          ├─ PlaybackEngineFactory 按容器选内核（自动 / 系统 / VLC）
          ├─ AVPlayerEngine：AVURLAsset + KVO + 0.1s 周期时间观察者
          ├─ VLCPlayerEngine：VLCMediaPlayer + drawable，0.1s 轮询时间
          ├─ 失败或 15s 无画面 → 自动切 VLC 并从当前位置续播
          ├─ 加载内嵌字幕轨 / 外挂字幕（SubtitleParser）
          └─ 退出时上报进度（Notification → LibraryStore）
      → SubtitleOverlayView 自绘渲染（两种内核一致）
```

字幕时间轴：`显示时间 = playerTime - delay`，因此正延迟表示字幕更晚出现。

VLC 内核以动态库形式内嵌（`Vendor/MobileVLCKit.xcframework`，构建前由脚本下载并校验 SHA256，打包时裁 arm64 后 ad-hoc 签名）。

### 4.3 传输

```
TransferManager.enqueueXxx → 任务入队 → pump()
  └─ Task（MainActor 继承）
       └─ ProviderFactory.make(config)
            ├─ download → HTTPFileTransfer（URLSessionDownloadDelegate 上报进度）
            ├─ upload   → HTTPFileTransfer（uploadTask + didSendBodyData）
            └─ copy     → provider.copy
```

暂停 = 取消 Task（下次继续从头开始）；进度回调经 `Task { @MainActor }` 回到主线程。

### 4.4 本机目录授权

`UIDocumentPicker` 选中的 URL 通过 `bookmarkData(.minimalBookmark)` 持久化；
`LocalAccessManager` 在启动时对每个本机来源调用 `startAccessingSecurityScopedResource()` 并长期持有，
`LocalFileProvider` 内部再各自持有一份作用域（成对释放），保证跨页面访问不失效。

## 5. 扩展指南

### 新增一种远程协议

1. 在 `SourceKind` 增加 case（标题、图标、能力）。
2. 实现 `RemoteFileProvider`（至少 `list` / `stream`，其余用默认实现）。
3. 在 `ProviderFactory.make` 注册。
4. 在 `AddSourceView` 增加对应表单字段。

### 新增一种字幕源

在 `SubtitleSearchService` 中增加一个私有方法，返回 `[SubtitleSearchResult]`，
并在 `search(code:options:)` 中并入结果即可（下载逻辑复用）。

### 扩展播放格式

`PlayerViewModel` 内聚了 AVPlayer 的一切。若接入 VLCKit，可把 `start()` 的加载分支替换为
`VLCMediaPlayer` 实现，同时保留 `currentTime / duration / cues` 三个对外接口，视图层无需改动。

## 6. 已知取舍

- 云盘上传未实现：需要分片、秒传与预签名流程，且各平台差异极大。
- 云盘 OAuth 未内置：应用需注册 client_id，当前以 Token 粘贴方式接入。
- SMB 采用"先缓存再播放"，因为无法把 SMB 文件映射为支持 Range 的 URL。
- 媒体库为全量 JSON 快照，条目数量在数千级别时性能良好；再大建议改为 SQLite。
